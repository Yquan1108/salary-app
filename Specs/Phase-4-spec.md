# phase-4-spec.md

## Phase 4 Name
工资统计与 Excel 导出

## Goal
让用户可以按照员工和做工时段筛选做工记录，查看工资明细，并导出 .xlsx 到本地公开目录，导出完成后支持直接打开文件。

## In Scope
1. 工资统计页面
2. 按员工筛选
3. 按日期区间筛选
4. 展示工资明细列表
5. 汇总金额
6. 导出 .xlsx
7. 导出后打开文件

## Out of Scope
1. 复杂财务报表
2. 自动算税
3. 云端分享
4. PDF 导出

## User Stories
1. 作为包工头，我想按员工查看一段时间内的做工和工资。
2. 作为用户，我想导出工资表发给老板或自己留档。
3. 作为用户，我想知道导出的文件保存到了哪里，并且可以直接打开。

## Functional Spec

### 1. 筛选区域
支持：
- 员工选择
- 日期起始
- 日期结束
- 可选工地筛选（建议加入）

操作：
- 点击查询
- 点击重置

### 2. 结果列表
列表按精简表格样式展示：
- 日期
- 员工
- 工地
- 做工时长
- 员工电话
- 工价
- 金额

底部或顶部显示：
- 记录总条数
- 金额总计

说明：
- 金额总计基于 amount 字段解析
- 若某条 amount 格式非法，应在开发阶段定义容错策略
- MVP 建议：仅统计可解析数字，异常值在 UI 中提示

### 3. Excel 导出
导出文件：
- 格式：.xlsx
- 保存位置：公开可见目录，优先下载目录
- 文件名建议：
  - 工资统计_员工名_开始日期_结束日期.xlsx
  - 若无员工筛选，则使用“全部员工”

表格内容至少包含：
- 标题
- 导出时间
- 筛选条件
- 明细表头
- 明细数据
- 合计金额

### 4. 导出完成反馈
要求：
- 弹窗提示导出成功
- 显示保存位置的用户友好描述，例如“已保存到下载”
- 提供“打开文件”按钮
- 打开失败时给出错误提示

### 5. 空数据处理
- 没有筛选结果时，不允许导出空表，或允许但需明确提示
- 建议 MVP：无数据时禁用导出按钮或点击提示“暂无可导出数据”

## Data / Export Rules
1. 统计只基于已保存的 WorkRecord。
2. 统计金额以用户手动录入的 amount 为准。
3. Excel 内容必须与当前筛选结果一致。
4. 导出文件必须在用户容易找到的位置。
5. 导出后要可以调用系统打开文件。

## UI States
1. 初始态：
   - 提示选择员工和时间范围
2. 无结果态：
   - 暂无符合条件的数据
3. 有结果态：
   - 展示表格列表和合计
4. 导出成功态：
   - 成功弹窗 + 打开文件
5. 导出失败态：
   - 提示失败原因

## Acceptance Criteria
1. 可按员工筛选做工记录。
2. 可按日期区间筛选做工记录。
3. 列表正确显示筛选结果。
4. 可显示总金额与记录数。
5. 可导出 .xlsx 到公开目录。
6. 导出成功后可点击打开文件。

## QA Checklist
1. 仅选员工，不选日期时的行为是否符合设计。
2. 起始日期晚于结束日期时是否拦截。
3. 无结果时导出按钮是否正确处理。
4. 导出的 Excel 是否能被常见表格工具打开。
5. 表头、内容、合计是否正确。
6. 中文文件名是否正常。
7. 打开文件按钮是否有效。
