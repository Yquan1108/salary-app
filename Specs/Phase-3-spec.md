# phase-3-spec.md

## Phase 3 Name
图片上传与图片管理模块

## Goal
让用户能够按“日期 + 工地”保存一批工地照片，支持拍照、相册多选、压缩保存、本地查看、批量删除、单张下载到系统相册。

## In Scope
1. 拍照上传
2. 相册多选上传
3. 一次上传作为一个批次保存
4. 上传前填写日期和工地
5. 图片本地压缩与持久化存储
6. 图片批次列表展示
7. 批量删除
8. 单张下载到系统相册
9. 上传结果提示与打开能力

## Out of Scope
1. 图片搜索
2. 云同步
3. AI 识图

## User Stories
1. 作为包工头，我想一次上传多张工地照片，并记住是哪个工地、哪一天的。
2. 作为用户，我希望以后老板要照片时能快速找到。
3. 作为用户，我希望照片安全保存在本地，不依赖临时缓存。
4. 作为用户，我希望某张照片能单独下载到相册，方便发给别人。

## Functional Spec

### 1. 图片上传入口
支持两种方式：
- 直接拍照
- 从系统相册多选

上传前表单：
- 日期：必填，默认今天
- 工地：必填，支持从工地档案选择
- 备注：选填

规则：
- 选完图片后再进入确认上传页，或先填元数据后选图，二者择一，但流程必须简单
- 一次上传多张图片，保存为一个 PhotoBatch
- 上传时对图片进行压缩
- 压缩后的图片保存到本地持久目录
- 不依赖缓存目录作为正式存储

### 2. 图片列表页
展示逻辑：
- 一次上传为一条记录
- 每条记录展示：
  - 日期
  - 工地名称
  - 图片数量
  - 缩略图区域

缩略图区域要求：
- 类似相册布局
- 根据图片数量动态调整每行显示数量
- 视觉美观
- 支持放大缩小网格密度
- 可以通过双指缩放或提供分档切换作为替代方案

说明：
- 若 Compose 下双指缩放实现复杂，可先做“2列/3列/4列切换”版本，保证可用性优先

### 3. 图片详情/预览
- 点击缩略图进入单张预览
- 可左右查看同批次图片
- 提供下载按钮
- 下载到系统相册
- 下载成功后弹出提示，并可点击打开系统相册或对应图片

### 4. 批量删除
支持对上传批次进行多选删除：
- 多选批次
- 删除前确认
- 删除时同时删除本地图片文件
- 删除成功后提示数量

### 5. 权限与异常
- 相机权限按需申请
- 相册读取权限按 Android 版本适配
- 权限被拒绝时，展示清晰引导
- 存储失败、压缩失败、图片损坏时，要有提示

## Data Spec

### PhotoBatchEntity
- id: Long
- workDate: Long
- siteId: Long?
- siteNameSnapshot: String
- remark: String?
- photoCount: Int
- createdAt: Long
- updatedAt: Long

### PhotoItemEntity
- id: Long
- batchId: Long
- localUri: String
- localPath: String
- originalFileName: String?
- width: Int?
- height: Int?
- sizeBytes: Long?
- createdAt: Long

## Storage Rules
1. 上传后的正式文件必须持久化保存。
2. 删除批次时，数据库记录和本地文件都要删除。
3. 下载到相册时，使用 MediaStore 写入公开相册目录。
4. 下载完成后返回可感知反馈。

## UI States
1. 空态：
   - 还没有上传照片
   - 按钮：上传照片
2. 正常态：
   - 批次列表
   - 每批次含缩略图网格
3. 多选态：
   - 显示已选批次数量
4. 预览态：
   - 单图大图查看
   - 下载按钮
5. 权限拒绝态：
   - 说明为何需要权限
   - 提供重试/去设置

## Acceptance Criteria
1. 用户可以拍照并保存为一条图片批次。
2. 用户可以从相册多选图片并保存。
3. 批次列表能展示日期、工地、图片数量和缩略图。
4. 图片经过压缩后仍能正常查看。
5. 用户可以下载单张图片到系统相册。
6. 用户可以批量删除图片批次。
7. 删除后本地文件同步清理。

## QA Checklist
1. 拍照上传 1 张是否成功。
2. 相册多选 5 张是否成功。
3. 上传后杀掉 App 重开，图片是否仍能显示。
4. 删除批次后，图片是否真的从本地删除。
5. 下载到相册后，系统相册中是否可见。
6. 权限拒绝后是否有清晰提示。
7. 大图预览时图片切换是否正常。
8. 多图批次缩略图布局是否整齐。

## Phase 3 体验修正与增强规范（必做）

### 背景问题
当前 Phase 3 已实现基础功能，但存在以下用户体验问题：

1. 上传图片时工地无法复用已有工地档案，必须手动输入
2. 缩略图布局需要用户手动选择列数，不符合直觉
3. 图片下载后没有任何提示，用户不知道是否成功
4. 图片预览页返回逻辑错误，使用系统返回手势会直接返回首页，而不是退出预览

本节用于修正以上问题，提升实际使用体验。

---

## 1. 工地选择能力增强（上传时）

### 问题
当前图片上传时：
- 工地只能手动输入
- 无法复用已录入的工地档案

### 修正要求

图片上传页面中的“工地”字段必须支持：

1. 手动输入工地名称
2. 从已有工地档案中选择

实现要求：
- 显示为输入框 + “从档案选择”按钮
- 点击按钮弹出工地列表（BottomSheet 或 Dialog）
- 选择后自动回填输入框
- 若用户手动输入，也允许保存

数据规则：
- 若选择档案：保存 siteId + siteNameSnapshot
- 若手动输入：siteId = null，仅保存 siteNameSnapshot

---

## 2. 缩略图布局智能化（必须优化）

### 当前问题
- 用户需要手动选择“一行几列”
- 不符合普通用户使用习惯
- 对中老年用户不友好

### 修正目标
缩略图布局应“自动适配”，而不是依赖用户设置。

### 实现要求（至少满足其一）

#### 方案 A（推荐）
自动网格：
- 根据屏幕宽度自动计算列数（2~4列）
- 图片大小保持统一比例（正方形或接近）
- 保证整体整齐、密度适中

#### 方案 B（可选增强）
支持双指缩放调整列数：
- 默认自动布局
- 用户可通过双指缩放改变密度
- 但不强制用户操作

### 禁止
- 不允许把“列数选择”作为主要交互
- 不允许用户必须手动设置才能正常查看

---

## 3. 图片下载反馈（必须补充）

### 当前问题
- 用户点击下载后没有任何提示
- 用户不知道是否成功

### 修正要求

当用户点击“下载图片”时：

必须提供完整反馈流程：

1. 下载开始（可选轻提示）
2. 下载完成后弹出提示：
   - 文案示例：  
     “已保存到相册”
3. 提供操作按钮：
   - 打开相册 / 查看图片（可选但推荐）

### 技术要求
- 使用 MediaStore 保存到系统相册
- 成功后返回 Uri
- 使用 Toast / Snackbar / Dialog 显示反馈

### 验收标准
- 用户无需猜测是否成功
- 用户能明确知道图片已保存在哪里

---

## 4. 图片预览返回逻辑修正（重要）

### 当前问题
在图片预览页面：
- 使用系统返回手势（或返回键）
- 直接返回首页 ❌
- 而不是返回图片列表 ❌

这是严重导航错误。

---

### 正确行为

在图片预览页：

#### 返回优先级应为：

1. 返回图片列表页（PhotoBatchList 或 PhotoSearch）
2. 而不是直接返回首页

---

### 实现要求

1. 使用 NavController 正确管理返回栈
2. 预览页面必须通过导航进入（而不是直接跳转替换）
3. 返回操作应使用：
   - navController.popBackStack()

4. 禁止：
   - 手动跳转首页替代返回
   - 清空导航栈导致无法正确返回

---

### 验收标准

1. 从列表进入预览
2. 使用返回手势
3. 必须回到原列表位置（而不是首页）

---

## 5. UI 可用性补充（缩略图区域）

### 要求

1. 每个图片批次区域必须清晰：
   - 日期
   - 工地名称
   - 图片数量

2. 缩略图区域：
   - 有明确边界或卡片感
   - 不要与背景混在一起

3. 点击图片：
   - 必须有明显点击反馈（缩放/波纹/高亮）
