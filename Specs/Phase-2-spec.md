# phase-2-spec.md

## Phase 2 Name
做工记录模块

## Goal
让用户能够方便地记录每日做工信息，并在当前页面以精简表格样式查看、筛选和批量删除记录。

## In Scope
1. 新增做工记录
2. 做工记录列表展示
3. 按日期查看
4. 批量删除
5. 基础筛选
6. 与员工/工地档案联动

## Out of Scope
1. Excel 导出
2. 工资统计汇总
3. 图片功能

## User Stories
1. 作为包工头，我想快速记录某天某个工人的做工和金额。
2. 作为用户，我希望员工和工地能直接选，不要每次重输。
3. 作为用户，我希望记录完后马上能看到当日记录。
4. 作为用户，我希望批量删除误录的数据。

## Functional Spec

### 1. 新增做工记录页面
输入项：
- 日期：必填，默认今天
- 员工姓名：必填，可手动输入，也可从员工档案选择
- 电话号码：选填，可手动输入
- 工地名称：选填，可手动输入，也可从工地档案选择
- 做工时长：选填
- 工价：选填，可手动输入
- 金额：必填，手动输入为准
- 备注：选填

规则：
- 金额必须可输入
- 工时、工价只作参考，不自动覆盖金额
- 保存成功后返回列表并提示“已保存”
- 可支持“继续新增”快捷操作

自动补全规则：
- 若用户从员工档案中选择员工，则自动填充：
  - 员工姓名
  - 电话号码（若档案中有）
  - 工价（若档案中有默认工价）
- 自动填充后，用户仍可手动修改电话号码和工价
- 用户手动修改后的值仅作用于当前记录，不反向修改员工档案
- 若用户未选择员工档案，而是直接手动输入员工姓名，也允许保存
- 工地同理：可手动输入，也可从工地档案中快捷选择
### 2. 做工记录列表页
展示形式：
- 每条记录一行
- 视觉上像精简表格
- 适合横向信息较多的场景
- 必要时支持横向滚动容器

每行至少显示：
- 日期
- 员工姓名
- 工地
- 做工时长
- 工价
- 金额

要求：
- 字体清晰
- 行高适中
- 支持长列表滚动

### 3. 筛选能力
至少支持：
- 按日期筛选
- 按员工筛选
- 按工地筛选

可先做单条件或组合筛选的最小可用版本。

### 4. 批量删除
要求：
- 列表进入多选模式
- 可全选/取消全选
- 删除前确认
- 删除后提示删除成功数量

### 5. 编辑记录
要求：
- 点击记录进入编辑页面
- 可以修改所有字段
- 保存后更新列表

## UI States
1. 空态：
   - 暂无做工记录
   - 按钮：新增记工
2. 正常态：
   - 顶部筛选栏
   - 中间记录表格列表
   - 底部悬浮新增按钮
3. 多选态：
   - 顶部显示已选择数量
   - 删除按钮
4. 编辑态：
   - 表单回填

#### UI 可用性要求（必须执行）

当前版本存在问题：输入区域与背景区分不明显，用户难以判断哪里可以点击和输入。

为解决该问题，新增做工记录页面必须满足以下 UI 规范：

1. 所有输入字段必须使用明确的输入框组件（TextField 或 OutlinedTextField）
   - 不允许使用“标签 + 空白区域”代替输入框
   - 输入框必须有清晰边界或背景

2. 输入框视觉规范：
   - 圆角：16dp
   - 背景：白色（或明显区别于页面背景）
   - 未聚焦边框：浅灰色
   - 聚焦边框：主色（绿色）
   - 内边距充足，避免贴边

3. 页面结构必须使用分组或卡片：
   - 基础信息（员工、电话、工地）
   - 做工信息（时长、工价、金额）
   - 备注
   - 每组之间必须有明显间距或卡片分隔

4. 员工、工地字段必须：
   - 显示为输入框
   - 旁边提供“从档案选择”按钮
   - 输入框与按钮视觉上分离

5. 自动补全字段（电话、工价）：
   - 必须仍然使用输入框展示
   - 不允许变成纯文本展示

6. 金额输入框必须视觉突出（因为是核心字段）

目标：
用户一眼能看出：
“哪里可以点，哪里可以输入”
## Interaction Rules
1. 保存失败要说明原因。
2. 删除前必须确认。
3. 必填项缺失时高亮提示。
4. 员工、工地优先使用档案选择器，而不是自由输入。
员工和工地字段必须同时支持：
  1. 直接手动输入
  2. 从常用档案中快捷选择

规则：
- 手动输入和档案选择都可完成保存
- 不要求必须先建档
- 若手动输入内容与已有档案匹配，可提供联想建议
- 保存做工记录时，应同时保存：
  - workerId / siteId（若选择了档案则保存对应 id；若纯手输则可为空）
  - workerNameSnapshot / siteNameSnapshot（始终保存最终显示名称）
5. 金额输入框要明显，避免用户误以为是自动计算。

## Acceptance Criteria
1. 用户可新增一条做工记录并成功保存。
2. 保存后列表立即显示新记录。
3. 可编辑已有记录。
4. 可按日期、员工、工地筛选。
5. 可多选删除记录。
6. 重启 App 后记录仍存在。

## QA Checklist
1. 金额为空能否拦截。
2. 员工未选择能否拦截。
3. 工地为空时是否允许保存。
4. 长姓名、长工地名是否挤坏布局。
5. 多选删除 1 条、3 条、全选是否都正常。
6. 编辑后列表是否实时更新。
7. 空列表和有数据列表切换是否正常。
